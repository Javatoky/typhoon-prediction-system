# 数据与模型工作流（组长协作手册）

本文件记录「数据与模型」这条线的工作模式、阶段划分、口径裁决规则与协作红线。
目的：让口径决策**可追溯**，让 AI 协作**可验证**，让三周后的我们不重复踩坑。

---

## 0 一句话定位

> 这个项目的数据工作**不是"收集 + 标注"，而是"数据集成 + 口径裁决 + 质量审计"**。

- IBTrACS 已是 NOAA/NCEI 整合好的**最佳路径档案**，没有原始观测要采集，也没有人工标注要做。
- 全部"标签"都是从观测值**按规则派生**：强度等级、质量标志、样本窗口。
- 因此真正的难点是**裁决口径**（用哪个机构的风速列、如何对待缺失、年份下限取多少），
  这是科学判断，**AI 不能替你签字**。

---

## 1 分工原则

| 交给 AI（可验证的机械工作） | 必须由组长亲自做（口径与取舍） |
| --- | --- |
| 写侦察 / 预处理 / 评估脚本 | 决定 `max_wind_mps` 用哪个机构列 |
| 统计缺失率、机构分歧、分布 | 判断异常值是剔除还是保留 |
| 查 IBTrACS 字段含义与官方文档 | 确认并**签字冻结**特征口径 |
| 生成数据集卡片与报告草稿 | 抽查原始数据与处理结果是否一致 |
| 穷举边界情况、写回归测试 | 划插值红线（不得为凑样本量而插值） |

**红线**：AI 不得擅自补缺失值、不得擅自改特征顺序、不得擅自扩大数据范围、
不得为了让指标好看而调整划分方式。每次产出必须声明"我没有动哪些东西"。

## 2 五个阶段

```text
阶段0 侦察  →  阶段1 冻结口径  →  阶段2 管道实现  →  阶段3 质量审计  →  阶段4 样本与划分
（是什么样）    （按什么标准）      （怎么算）        （算得对不对）     （怎么喂模型）
  AI 生成脚本     AI 起草+组长签字    AI 主写          AI 统计+组长抽查    AI 主写+组长验算
```

## 3 协作四条规则

### 规则 1：分工线 = 「可验证的代码和统计」归 AI，「口径和取舍」归组长
见第 1 节表格。

### 规则 2：每个产出必须自带「验证钩子」
AI 交付任何结论时，必须同时给出：

1. **可复现命令**（组长能独立跑出同样结果）
2. **具体抽样**（例如"某台风原始 5 行 vs 处理后 5 行"的对照）
3. **反例检测**（这条规则失效时输出会长什么样）

> 不允许出现"AI 说数据够了"这种无法验证的结论。

### 规则 3：对话结论必须落盘
任何在对话里达成的口径决策，**当轮写进 `docs/data-card.md`**；
未落盘的决策下一轮不认。

### 规则 4：决策留痕格式统一
每条口径决策记录四要素：

```text
决策：<选了什么>
备选：<还有什么选项>
理由：<为什么这样选，依据是什么>
影响：<对样本量/指标/报告的影响，需要披露什么>
```

## 4 已知的坑（IBTrACS 特有，按踩坑概率排序）

| # | 坑 | 后果 | 应对 |
| --- | --- | --- | --- |
| 1 | **CSV 有两行表头**，第二行是单位行 | 直接把单位当数据，全表类型错乱 | 读表时 `skiprows=[1]`（`data_recon.py` 已自动识别） |
| 2 | **风速单位是 knot**，不是 m/s | 强度等级全错（差 1.94 倍） | 统一乘 `KNOT_TO_MPS`，并保留原始列以备核对 |
| 3 | **各机构风速平均时段不同**（USA 1 分钟 / WMO 10 分钟） | 同台风同时刻数值差 10%+，等级分布随之变化 | 选定唯一训练列，其余仅作交叉校验，报告必须注明口径 |
| 4 | **时间间隔不全是 6 小时**（历史记录含 3 小时/不定时） | 无法构成 DQ-04 要求的连续窗口，样本被大量砍掉 | 体检表会给出精确占比，据此决定年份下限或降频策略 |
| 5 | **早期年份风速缺失极多** | 样本量骤减，但"看起来"数据很多 | 按年代统计缺失率（体检表第 2 节），据此定年份下限 |
| 6 | **NATURE ≠ TS 的记录**（温带变性、扰动等） | 把非台风阶段当月台风学习 | 训练样本只保留 `NATURE == TS` |
| 7 | **经度可能是 0~360** | 跨 180° 时出现 179 → -179 跳变 | 统一转 -180~180，并对跨线台风做连续性处理 |
| 8 | **同一台风多个机构行** | 若按行去重会混入多份"同一时刻不同值" | 按 `SID + ISO_TIME` 聚合并明确取值优先级 |
| 9 | **插值制造假观测** | 看似样本变多，实际引入数据泄漏与虚假精度 | 插值上限宁严勿宽；插值点必须 `quality_flag=interpolated` 且单独统计占比 |
| 10 | **按台风划分集合** | 同一台风的时间片跨集合 → 数据泄漏 → 指标虚高 | DQ-06 已强制按 SID 划分，划分后需验证交集为空 |

## 5 可复用脚本

| 脚本 | 作用 | 是否可重复执行 |
| --- | --- | --- |
| `backend/scripts/fetch_ibtracs.py` | 下载 IBTrACS 子集（支持断点续传） | 是（自动续传/跳过已完成） |
| `backend/scripts/data_recon.py` | 数据侦察，生成体检表与红旗清单 | 是（幂等，输出可覆盖） |
| `backend/scripts/verify_dataset.py` | 数据集完整性核验（形状/量纲/无泄漏/口径一致/跨 180° 跳变，全量样本） | 是（只读，退出码表示通过与否） |
| `backend/scripts/spot_check.py` | 阶段 3 抽查包：原始记录 vs 处理结果逐行对照 + 自检 | 是（只读原始数据，输出到 `data/review/spot_check/`） |
| `backend/training/prepare_data.py` | 构造训练样本 | 是 |
| `backend/training/train.py` | 训练 | 是 |
| `backend/training/evaluate.py` | 评估（含持续性基线对比） | 是 |
